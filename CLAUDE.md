# webmcp-adapter

Tools instead of selectors: the adapter injects WebMCP tools into web apps you don't own, so tests and agents call a tool (e.g. `uibank.applyForLoan`) instead of clicking through selectors. Results can be run and stored in UiPath Test Manager.

- Slides: https://www.reitermayer.com/UiPath-MVP/WebMCP-Adapter/slides.html
- Overview and background: [README.md](README.md)

This file tells you how to use the adapter. You only run the pipeline below - the runtime, scripts and tests are the machinery and are not edited while using it.

## What you need

1. Chrome 154 or later (or Edge 154 or later).
2. WebMCP switched on: `chrome://flags/#enable-webmcp-testing` (Edge: `edge://flags/#enable-webmcp-testing`), set to Enabled, then relaunch. Optional: `#devtools-webmcp-support` adds a WebMCP panel to DevTools.
3. Check in the browser console: `typeof document.modelContext` must be `"object"`, not `"undefined"`.
4. Node.js and `npm install` in this folder (installs Playwright).
5. For Discover: Claude Code with a browser tool (Claude in Chrome or Playwright MCP).
6. Optional, for Report: UiPath Test Cloud with Test Manager, a serverless robot, and the `uip` CLI logged in to your tenant.

No Studio Desktop, no Object Repository, no Windows VM - a Mac and a browser are enough.

## The pipeline: five stages, four commands

Only the first stage uses AI. Run them in this order, in Claude Code:

| Stage | Command | What it does | What it writes |
|---|---|---|---|
| 1 Discover | `/discover <url of the form>` | An agent explores the form once in a real browser: scans the fields, finds the business rules the app states, probes them with dummy data. | `discovery/<app>-<form>.raw.json`, `discovery/<app>-<form>.probes.json`, `manifests/<app>.manifest.json` |
| 2 Generate | `/generate` | A script turns the manifest rules into boundary test cases (just below and at every limit) plus one smoke test. Combinations no rule covers are listed as gaps. | `tests/cases/*.cases.json`, one `test()` line per case in the spec |
| 3+4 Inject and execute | `/inject-execute` (short: `/run-tests`) | Playwright opens Chrome, injects the adapter into every page and each test calls the tool. The form fills itself: fields flash orange, then a green banner. | `playwright-report/`, `test-results/` |
| 5 Report | `/report` | Packs the same tests, uploads them, lets Test Manager create one test case per test and runs them on a serverless robot. | Results, screenshots and traces in Test Manager |

Example: `/discover https://uibank.uipath.com/loans/apply`

`/devtools-demo` prepares the adapter for your own Chrome, so you can run a tool by hand from the DevTools WebMCP panel - no Playwright, no extension.

## Good to know

- **Earlier results are set aside, never deleted.** Discover and Generate move the previous files to `backup/runs/<date_time>-<stage>/` before they start.
- **Discover submits real forms.** It uses dummy data only (`webmcp.test@example.com`, round numbers) and a handful of submissions. Point it at demo or test systems, not at production.
- **The manifest holds only confirmed rules.** A rule goes in only if the app states it and a probe confirmed it. Everything else is listed under `openQuestions` in the manifest - read them after a discovery.
- **Run Discover again when the app changes.** The manifest is the only place that knows selectors; tests and tools stay as they are.
- **A test checks two things:** first the adapter (no error, result seen, audit clean - only the tool touched the form), then the business outcome against the rule. A failure tells you which of the two it was.
- **Write tools ask for confirmation** (`confirm: true`). This guards against accidental calls; it is not a security control.

## Using your own Test Manager

All settings are in [testmanager.json](testmanager.json): tenant, project, test set, package and robot. Replace the values with your own before running `/report` (or put them in `testmanager.local.json`, which Git ignores and which overrides `testmanager.json` section by section). The login is not in this repo - it comes from `uip login`.

- The serverless robot account must be a member of the Test Manager project, otherwise the results cannot be uploaded.
- Playwright in Test Manager runs on serverless robots in UiPath's cloud, with Chromium only. Apps that are only reachable inside a company network need connectivity from there.
- Nothing is ever deleted in Test Manager. Remove old test cases and test sets by hand.

## Where things are

- `manifests/` - the app knowledge, one file per app (generated by Discover)
- `discovery/` - the evidence behind the manifest: raw scan and probes
- `tests/cases/` - generated test cases; `tests/*.spec.js` - the tests that call the tools
- `runtime/` - the generic adapter runtime, the same for every app
- `.claude/skills/` - the commands above
